pthread_join() usage:

In creatPhilosophers(), after allof the threads are created, a second loop calls
pthread_join() on each thread handle. This will block the main thread until
each philosopher thread finishes. All threads must complete before the
function prints the completion message and returns.

My condition var design:

A single mutex (orderMutex) and condition var (orderCond) control
eating order. The integer nextIndex starts at 0 and tracks whose turn it is.

After thinking, philosopher i locks orderMutex and waits in a while loop
until nextIndex == i:

    pthread_mutex_lock(&orderMutex);
    while (nextIndex != philosopher)
        pthread_cond_wait(&orderCond, &orderMutex);

pthread_cond_wait atomically releases the mutex and suspends the thread.
When a philosopher finishes eating, it increments nextIndex and calls
pthread_cond_broadcast() to wake all waiting threads, then unlocks:

    nextIndex++;
    pthread_cond_broadcast(&orderCond);
    pthread_mutex_unlock(&orderMutex);

All woken threads recheck the while condition. Only the one where
nextIndex == i proceeds; the rest go back to sleep. The while loopis necessary because broadcast wakes everyone and spurious wakeups are also possible.

Deadlock prevention:

Deadlock requires hold-and-wait: a thread holds one resource while
blocking on another. pthread_mutex_trylock() breaks this by returning
immediately if the lock is unavailable instead of blocking. If a philosopher gets the left chopstick but trylock fails on the right, it immediately releases the left and backs off for a random interval
before retrying. Since no thread ever blocks while holding a chopstick,
hold-and-wait cannot occur and deadlock is impossible. The random backoff will also prevent when all philosophers retry
in lockstep and never make progress.
