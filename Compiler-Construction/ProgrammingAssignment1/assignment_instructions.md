## Requirements

Write a program that checks whether XML-like elements in the input are properly balanced.

- **You must use ANTLR4 lexer only** (no parser rules). All balancing logic is implemented in Java.

---

## Background: XML Elements and Balance

An XML element is a structural unit that begins with an opening tag (e.g., `<div>`), ends with a matching closing tag (e.g., `</div>`), and may contain text or other elements in between. Some elements are self-closing (e.g., `<br/>`) and do not enclose any content. In well-formed XML, each opening tag must have a corresponding closing tag with the same name.

XML elements are **nested**, meaning elements can appear inside other elements. This nesting must follow a strict last-opened, first-closed rule. For example, `<a><b></b></a>` is balanced, while `<a><b></a></b>` is not. An input is considered balanced if every opening tag is closed exactly once, closing tags appear in the correct order, and no unmatched opening or closing tags remain at the end of the document.

## An Example of Properly Balanced XML Document

The document below is an example of a balanced XML input. The indentation and multi-line layout are provided only for clarity and are not required. Whitespace, including tabs and line breaks, is insignificant.

```xml
<header>
  Is this the real life?
</header>

<section>
  <article>
    Is this just fantasy?
    <p>
      Caught in a <br/> landslide,
    </p>
    <div>
      No escape from reality.
      <span>
        Open your eyes,
      </span>
    </div>
  </article>
  <footer>
    Look up to the skies and see.
  </footer>
</section>

<nav>
  I'm just a poor boy, I need no sympathy.
</nav>
```

## Input Language

The input is a simplified XML-like text with the following rules:

- **Opening tags:** `<name>`
- **Closing tags:** `</name>`
- **Self-closing tags:** `<name/>`
- Tag names are C-style identifiers except that letters must be lower-case. Your scanner is expected to fail to recognize any tag names that do not conform to that.
- Arbitrary text may appear anywhere inside (and outside) the elements. Such text never contains `<` or `>`.
- Multiple top-level elements are allowed.

---

## Error Reporting

Use the following fixed output formats:

- If a closing tag doesn’t match the most-recent unclosed opening tag, report:
  - `ERROR: UNMATCHED-CLOSE </name>`
- After processing the entire file, all remaining open tags must be reported (from most recent to oldest) as:
  - `ERROR: UNMATCHED-OPEN <name>`
- Your program should stop as soon as it encounters an error. Otherwise, it should print a single line saying `OK`.

## Scanner Error(s)

When your program is given the following input:

```
<a></A>
```

The expected output is:

```
line 1:3 token recognition error at: '</A'
line 1:6 token recognition error at: '>'
ERROR: UNMATCHED-OPEN <a>
```

Here, the first two lines are generated by the ANTLR4 scanner, not the driver. This is the expected behavior. Later, we will learn how to process scanner errors from within the driver.
